# Benchmark results — 2026-10-16

Status: Measured values (principle P-010). Targets are in `docs/13-test-plan.md` section 7.

## 1. Setup

| Item | Value |
|------|-------|
| Computer | Apple M4 Pro, 24 GiB RAM, internal SSD |
| OS | macOS 26.5.1 |
| Build | `cargo build --release`, Rust 1.99.1 |
| Daemon settings | Defaults (`config/default.toml`): 4 workers, `sync_writes = true`, debounce 200 ms |
| Corpus | `benchmarks/corpus-generator/generate.py` — 885 files, 100,005 lines (Rust, TypeScript, Python), one Git commit |
| Client | `benchmarks/end-to-end/bench.py`, one persistent loopback HTTP connection. All timings include the HTTP round trip. |
| Iterations | 1000 per operation (20 for the file change) |
| Cache | "Warm": OS file cache and RocksDB block cache warm. Uncached operations change the token budget per call, so the L0 cache never answers them. |

## 5. Tokens

All 20 fixed queries of TK-01 stay at or below the default budget of 250 estimated tokens
(`tests/token-regression/baseline.json`). Benchmark responses: 162–229 tokens at budget 250.

## 6. Limits of this report

- One corpus size (100k lines). The 1M and 5M line corpora are later work (`docs/12-development-plan.md` section 8).
- macOS `fsync` does not force the drive cache (`F_FULLFSYNC`). Capture latency on Linux with `fdatasync` can differ.
- Recall was not measured with a labelled query set.
