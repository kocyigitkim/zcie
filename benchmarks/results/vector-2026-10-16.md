# Vector search evaluation — 2026-10-16 (ADR-011)

Script: `benchmarks/vector/eval.py <samples> <model> <work>`. Corpus: the three sample projects of `benchmarks/samples/generate.py`
(ledger-rs, atlas-ts, orbit-py; 8,527 lines) and one decision per project in the memory. A separate daemon indexes them; the same
store is queried with vector search off (`ZCIE_VECTOR_ENABLED=false`) and on. A result counts if the expected title part is in the
title or the snippet of one of the first 10 results. The parameters (cosine ≥ 0.30, RRF k = 60) were set before the evaluation
and were not tuned on it.

Groups: **paraphrase** — other words, some shared with the code or the doc comments; **hard** — no content word shared with the
code, the doc comments or the decisions; **memory** — decisions; **exact** — the name is in the question.

## 3. Findings

- Vector search helps where the words differ: hit@5 19 → 22 of 28, MRR 0.586 → 0.661. Exact-name questions do not change.
- The gain is largest for memory questions (MRR 0.500 → 0.778): decisions are short texts, and a mean of word vectors fits them.
- Static embeddings know common English words. Questions with rare words ("tardy remittance", "memoized", "propulsion")
  still fail. The 4× larger `potion-retrieval-32M` did not do better (MRR 0.632), so the 31 MB `potion-base-8M` is the default.
- The doc comments that the symbol documents now include (ADR-011 section 2) raised the lexical baseline too; the "off" column
  already has them.
- The labelled set is small (28 questions on 3 small projects). The values show the direction, not a general recall figure.
